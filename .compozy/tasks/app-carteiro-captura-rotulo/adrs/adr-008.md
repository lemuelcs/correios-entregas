# ADR-008: Extração dos campos livres com Gemini flash-lite chamado direto do backend, schema com dúvida por campo

## Status

Accepted

## Date

2026-09-30

## Context

A regra de revisão (ADR-002) exige saber, por campo, se a leitura é segura. O OCR do Prosio (`runOcrExtraction`) é interno ao fluxo de mídia do WhatsApp, não tem rota HTTP e devolve um registro livre sem confiança por campo. O backend do correios-entregas declara SDKs de LLM sem usá-los. O Prosio usa `gemini-3.1-flash-lite` em prod.

## Decision

- O backend chama o modelo de visão diretamente, com o AI SDK (`ai` + `@ai-sdk/google`) e `generateObject`, sobre um schema zod fixo: para cada campo (nome, telefone, logradouro, número, complemento, bairro, CEP em texto, código em texto), `{ valor: string | null, duvida: boolean, motivo?: string }`.
- Modelo e provedor vêm do ambiente: `CAPTURA_AI_PROVIDER=google`, `CAPTURA_AI_MODEL=gemini-3.1-flash-lite`, `CAPTURA_AI_API_KEY`.
- O prompt proíbe inventar: um caractere não lido deixa o campo com `duvida=true`, e um campo ausente fica `valor=null`.
- O timeout é de 15 s. Um erro ou timeout gera o resultado "extração indisponível": a captura vai para Para conferir com os campos vazios.
- Tokens e custo estimado ficam gravados na `Captura`.

## Alternatives Considered

### Alternative 1: Expor o OCR do Prosio por API

- **Description**: criar uma rota no Prosio (via hub) e chamá-la.
- **Pros**: reaproveita o ledger de custo e a política LGPD do tenant.
- **Cons**: mudança em outro produto e um schema genérico sem dúvida por campo.
- **Why rejected**: acopla dois produtos por uma função de uma chamada.

### Alternative 2: Claude Haiku 4.5

- **Description**: o mesmo desenho, com outro provedor.
- **Pros**: leitura forte de texto difícil.
- **Cons**: custo maior por rótulo.
- **Why rejected**: flash-lite já está provado em prod no Prosio. O provedor fica trocável por ambiente.

## Consequences

### Positive

- A regra de revisão tem um sinal explícito por campo.
- O provedor é trocável sem mudar código.

### Negative

- É necessário provisionar uma chave (`GOOGLE_AI_API_KEY` está vazia no `.env` atual).

### Risks

- O modelo pode não marcar dúvida quando deveria. Mitigação: validações determinísticas depois da extração (formato de telefone, CEP de 8 dígitos, nome não vazio) forçam dúvida. O código e o CEP vêm dos códigos de barras, não do LLM.
- A aposentadoria de ids de modelo (a geração 2.5 do Gemini já deu 404). Mitigação: o id fica no ambiente, e uma falha vira Para conferir, nunca perda de captura.

## Implementation Notes

A imagem é enviada como JPEG já comprimido pelo aparelho. Nenhum conteúdo da imagem ou dos campos vai para log.
