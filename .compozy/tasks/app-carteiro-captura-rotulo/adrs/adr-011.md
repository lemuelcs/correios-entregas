# ADR-011: Leitura dos três códigos no aparelho com zxing-wasm; DataMatrix > código linear > OCR, por campo

## Status

Accepted

## Date

2026-09-30

## Context

O rótulo dos Correios traz o código do objeto (Code 128), o código do CEP e um DataMatrix no layout SIGEP, com CEP, número, complemento e DDD+telefone do destinatário (telefone zerado quando ausente). A leitura precisa funcionar offline e também no iPhone, onde o `BarcodeDetector` não está disponível.

## Decision

- O app usa `zxing-wasm` (leitor) para decodificar a foto parada, depois do disparo, em Code 128 e DataMatrix. Não há detecção contínua no preview.
- O parser `parseSigepDataMatrix` extrai do DataMatrix: CEP de destino, código do objeto, número, complemento e telefone. Telefone só com zeros vira nulo.
- Fonte de cada campo, em ordem de precedência:
  - código: DataMatrix = Code 128 (divergência entre os dois vira dúvida) > digitado;
  - CEP: DataMatrix > código linear do CEP > texto do LLM (com dúvida);
  - número, complemento e telefone: DataMatrix > LLM;
  - nome, logradouro e bairro do rótulo: sempre o LLM (logradouro e bairro só quando o CEP não resolve);
  - logradouro, bairro, cidade e UF: CEP (ADR-009).
- Um campo vindo de código de barras válido nunca é duvidoso.
- A validação S10 roda no aparelho (offline) e de novo no servidor.

## Alternatives Considered

### Alternative 1: Só os dois códigos lineares

- **Description**: o desenho original do PRD.
- **Pros**: mais simples.
- **Cons**: telefone, número e complemento sempre pelo LLM, com mais dúvida e mais custo.
- **Why rejected**: o dono do produto escolheu ler o DataMatrix.

### Alternative 2: BarcodeDetector nativo mais fallback

- **Description**: a API do navegador no Android, a biblioteca no iPhone.
- **Pros**: sem WASM no Android.
- **Cons**: dois caminhos para testar, e suporte a DataMatrix incerto.
- **Why rejected**: um caminho só, testável com imagens.

## Consequences

### Positive

- Menos dúvida, menos custo de LLM, e o telefone vem com certeza quando o remetente o informou.

### Negative

- O WASM (cerca de 1 MB) entra no bundle do app do carteiro (com carregamento sob demanda e cache pelo service worker).

### Risks

- As posições do layout SIGEP precisam ser confirmadas contra rótulos reais. Mitigação: um fixture de rótulos reais anonimizados; um DataMatrix que não parseia é ignorado, e o fluxo cai no linear mais LLM.
- Rótulos de outros layouts (internacional, logística reversa). Mitigação: mesma regra de fallback.

## Implementation Notes

O parser vive num módulo compartilhado por aparelho e servidor (`shared/sigep-datamatrix.ts`, duplicado ou em pacote; decisão das tasks). O servidor revalida o que o aparelho mandou; nunca confia cegamente.
