# ADR-007: Validação do código S10 com dígito verificador e texto neutro da mensagem

## Status

Accepted

## Date

2026-09-30

## Context

Um código digitado errado notifica a pessoa errada sobre a encomenda de outra. O código S10 dos Correios tem dígito verificador (módulo 11, pesos 8,6,4,2,3,5,9,7), e o correios-entregas já tem esse validador. O texto proposto começava com "Sr. NOME", mas a lista não traz gênero.

## Decision

- Uma linha só é aceita com código no formato 2 letras + 8 dígitos + dígito verificador correto + 2 letras. Linha inválida é barrada na prévia com o motivo.
- A mensagem usa "Olá, <primeiro nome>", sem pronome de tratamento.

## Alternatives Considered

### Alternative 1: Somente o formato (2 letras + 9 dígitos + 2 letras)

- **Description**: Sem conferir o dígito.
- **Pros**: Aceita qualquer código bem formado.
- **Cons**: Deixa passar erro de digitação.
- **Why rejected**: Risco de notificar a pessoa errada.

### Alternative 2: "Sr./Sra." por coluna opcional

- **Description**: A lista traz o tratamento.
- **Pros**: Formalidade.
- **Cons**: Mais uma coluna, pouca adesão.
- **Why rejected**: Neutro resolve sem custo.

## Consequences

### Positive

- Erros de digitação são barrados antes do envio.

### Negative

- Códigos de teste precisam ter dígito válido (o exemplo AB123456789BR falha; o dígito correto seria 5).

### Risks

- Códigos internacionais com sufixo diferente de BR: aceitos se o formato e o dígito conferem.

## Implementation Notes

O validador existente (`s10.ts`) só aceita o sufixo BR; esta feature aceita qualquer sufixo de 2 letras, porque encomendas internacionais chegam com o país de origem.
